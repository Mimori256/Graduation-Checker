# 新しい年度・学類の卒業要件を追加する

このマニュアルは、開発者が入学年度・学類・専攻ごとの卒業要件を登録するための手順です。要件は [src/data/gradRequirementData.ts](../src/data/gradRequirementData.ts) の `gradRequirementData` に TypeScript のオブジェクトとして記入します。独立した JSON ファイルを追加しても、自動では読み込まれません。

## 1. 元資料と変更点を確認する

対象の**入学年度**に適用される履修要覧・卒業要件表を用意し、次を確認します。授業を履修した年度とは区別してください。

- 学類・専攻の正式名称と対象の入学年度
- 必修科目名、代替科目、科目区分ごとの必要単位数
- 選択科目の対象となる科目番号と、各条件・科目グループの最低・最高単位数
- 必修・選択・卒業に必要な総単位数

近い年度・専攻の既存データをコピーして編集すると進めやすくなります。ただし、数値や科目名を元資料と照合し、既存年度の要件を上書きしないでください。PR には参照した資料名・年度・ページや URL と、変更点を記載します。

## 2. データのキーとヘッダーを追加する

キーには既存の命名に合わせて「学類（必要なら専攻）の識別子 + 入学年度の下2桁」を使います。例は `mast-25`、`klis-irm-22` です。キーは重複させません。

```ts
// gradRequirementData の中に追加する例（値は説明用の仮の要件）
"example-26": {
  header: {
    department: "サンプル学類",
    major: "サンプル専攻",
    enrollYear: 2026,
  },
  courses: {
    compulsory: ["卒業研究A", "情報::4"],
    compulsorySumUnit: 10,
    select: [
      [["XX1"], 60, 80, false, "専門科目選択", 0],
      [["*外国語"], 4, 8, false, "外国語", 1],
      [["XX", "*外国語"], 30, 50, true, "関連科目選択", 2],
    ],
    selectMinimumUnit: 114,
    groups: [
      [0, 60, 80, "専門科目選択"],
      [1, 4, 8, "共通科目選択"],
      [2, 30, 50, "関連科目選択"],
    ],
  },
},
```

`department` と `major` は結果画面の表示名です。`enrollYear` は数値、または `"2022~2024"` のような表示用の文字列にできます。この文字列だけで年度の範囲を判定することはありません。複数年度をまとめる場合は、要件が共通であることを確認し、後述の年度選択処理も合わせて設定します。

## 3. 必修科目を記入する

`courses.compulsory` は文字列の配列です。次の3種類を使用できます。

| 記法                 | 記入例                                | 判定内容                                                     |
| -------------------- | ------------------------------------- | ------------------------------------------------------------ |
| 科目名               | `"卒業研究A"`                         | CSV の科目名との完全一致で検索する                           |
| 科目区分と必要単位数 | `"体育::2"`                           | 定義済みの区分に含まれる科目から2単位以上を集計する          |
| 科目名と代替科目一覧 | `"微分積分A//['微積分1', '微積分2']"` | 元の科目が見つからない場合、代替科目をすべて満たすか確認する |

科目名の空白・記号・全角半角も一致させてください。代替科目一覧は「いずれか1科目」ではなく**全科目**が必要です。また、元の科目が CSV に存在すると、成績が D・F でも代替科目の判定へ切り替わりません。

`::` の左側には [courseCodeTypes.ts](../src/consts/courseCodeTypes.ts) の `codeType` に存在する区分名を指定します。必要単位数は現在の実装では整数として読み込まれるため、`"区分::1.5"` のような小数の要件には判定処理の変更が必要です。

`compulsorySumUnit` は必修全体の必要単位数です。配列から自動計算されないため、元資料に基づいて手動で設定します。必修として検出された科目は選択科目の判定対象から除かれます。区分指定では必要単位数を超えた分も選択科目に回らないため、「必修に2単位、残りを選択に算入」のような要件はデータだけで表現できません。

## 4. 選択科目を記入する

`courses.select` の各行は、以下の順序の6要素です。

```ts
[["GC5", "GA4"], 20, 35, false, "GC5, GA4", 0];
// 対象コード一覧、最低単位、最高単位、除外条件か、表示名、グループID
```

| 位置 | 内容           | 記入方法                                                                  |
| ---- | -------------- | ------------------------------------------------------------------------- |
| 0    | 対象コード一覧 | 科目番号の接頭辞、または `*` を付けた区分名の配列                         |
| 1    | 最低単位数     | その行で必要な単位数。最低条件がなければ `0`                              |
| 2    | 最高単位数     | 元資料の上限を記入する                                                    |
| 3    | 除外条件       | `false` は一覧に該当する科目、`true` は一覧の区分を除いた科目を対象にする |
| 4    | 表示名         | 画面に表示する説明                                                        |
| 5    | グループID     | `groups` の対応する ID と同じ数値                                         |

科目番号は前方一致で検索します。`"GC"` は `GC` で始まるすべての番号を含みます。複数のコードは OR 条件です。`"*学士基盤科目"` のような区分指定では、`codeType` の `codes` と `except` を使います。

`true` に区分を指定すると、その区分の `codes` を除外し、`except` に該当する科目は対象に戻します。例えば `[["GA", "GB", "GC", "GE", "*総合科目", "*教職に関する科目"], 6, 15, true, "他学群の授業科目", 3]` は既存データの除外条件の例です。

**選択条件どうしの重複は自動で解消されません。** `"GC"` と `"GC5"` を別行にすると同じ科目が両方に集計されます。同じ行に `"GC"` と `"GC5"` を入れた場合も重複します。対象が重ならないように設計し、例外が必要なら判定処理も変更してください。

行の最高単位数は、現在のグループ集計では各行の単位数を切り詰めるために使われません。総計は後述の**グループの上限**で切り詰められます。行ごとの上限を厳密に適用する要件は、データの追加に加えて集計処理の変更が必要です。

## 5. 科目グループと選択全体の最低単位数を記入する

`courses.groups` の各行は4要素です。

```ts
[0, 20, 35, "専門科目選択"];
// グループID、最低単位、最高単位、表示名
```

同じグループ ID の選択条件が合算され、グループの最低単位数と比較されます。総計へ算入する際はグループの最高単位数までに制限されます。

現在の集計は `Object.values(groupCount)` と `groups` の配列位置を対応させています。ID は `0, 1, 2, ...` の連番にし、`groups` はその昇順で並べ、各グループに少なくとも1行の `select` を割り当ててください。

`selectMinimumUnit` は選択科目全体の必要単位数です。グループの最低単位数の合計から自動計算されるわけではありません。例えば既存の `mast-25` は必修51単位、選択73単位ですが、各グループの最低単位数の合計は73単位ではありません。総条件と各区分の条件をそれぞれ元資料から記入します。

## 6. 必要に応じて科目区分を追加する

新しい区分が必要なら [src/consts/courseCodeTypes.ts](../src/consts/courseCodeTypes.ts) に定義します。

```ts
サンプル区分: {
  codes: ["XX1", "XX2"],
  except: ["XX199"],
},
```

`codes` は対象となる科目番号の接頭辞、`except` は除外する接頭辞です。この例は `XX1`・`XX2` で始まる番号のうち `XX199` で始まるものを除きます。必修では `"サンプル区分::4"`、選択では `"*サンプル区分"` と記入します。未定義の区分名は実行時エラーになります。

区分定義は全年度・全学類で共有されます。既存区分を変更する場合は過去の要件への影響も確認し、年度ごとに異なる定義なら区分名を分けてください。

## 7. 画面の選択肢とデータの対応を更新する

データだけを追加しても画面から選択できません。次の箇所を更新します。

1. [src/consts/const.ts](../src/consts/const.ts) の `years` に新年度の表示値を追加します。新学類・専攻の場合は `majors` に識別子、`majorNames` に表示名を同じ位置で追加します。
2. [src/App.tsx](../src/App.tsx) の `getRequirement` に、選んだ識別子・年度から新しいデータキーへ対応させる分岐を追加します。
3. 同ファイルの `isMajor` の一覧に新しいデータキーを追加します。
4. [src/types/Major.ts](../src/types/Major.ts) の `Major` 型にも新しいデータキーを追加します。
5. 必要に応じて [README.md](../README.md) の対応年度・学類の説明を更新します。

例えば `mast-26` を追加するなら、`years` に `"2026"` を追加し、`getRequirement` に `year === "2026" && major === "mast"` のとき `"mast-26"` を選ぶ分岐を既存の最後の `else` より前に入れます。`isMajor` と `Major` にも `"mast-26"` を追加します。

現在、`getRequirement` は2021年度を `*-21`、mast の2025年度を `mast-25`、それ以外を `*-22` に対応させています。新しい年度を `years` に足すだけでは、旧年度のデータが選ばれます。また、現状は `mast-25` がデータと `isMajor` に存在する一方、`Major` 型には含まれていないため、更新時に一覧の整合性も確認してください。

年度の選択肢は全学類で共通です。新年度に対応するデータがない学類についても、どの要件を使うかを確認し、旧年度の要件を使うなら適用可能なことを元資料で確かめます。新学類を追加する場合も、画面で選べる全年度との組み合わせを確認してください。

初期表示も変更する場合は、[OptionSelector.tsx](../src/components/OptionSelector.tsx) の `DEFAULT_YEAR_INDEX` と `App.tsx` の `year` の初期値を揃えます。現在は前者が `years[1]`、後者が `years[0]` に相当するため、表示と内部の初期値が異なっています。

## 8. 追加後の確認

開発環境の準備は [README.md](../README.md#開発環境) を参照してください。リポジトリのルートで実行します。

```sh
pnpm typecheck
pnpm test --run
pnpm build
pnpm lint
pnpm dev
```

既存テストは主に `mast-21` を検証しているため、成功しても新しいデータの正しさは保証されません。新しい要件について次を確認します。

- 「卒業要件のみを表示」で、新年度・学類・専攻のヘッダーと条件が正しく表示される。
- 年度・学類を切り替えて、対応するデータが選ばれ、エラーにならない。
- サンプル成績で、必修の未履修・代替科目・区分単位数の判定が元資料と一致する。
- 選択の最低単位数の直前・到達時、グループの上限超過時の集計が想定どおりになる。
- 同じ科目が複数の条件に重複算入されず、対象外科目が正しく残る。

判定や集計を変更した場合は [src/test/compulsory.test.ts](../src/test/compulsory.test.ts) と [src/test/select.test.ts](../src/test/select.test.ts) を参考に、変更した条件や境界値を検証するテストを追加します。なお、現在は D・F を不合格として除外し、履修中の科目は集計に含めます。

### データ追加だけでは対応できない要件

[GraduationChecker.tsx](../src/components/GraduationChecker.tsx) の合計判定・表示は **124単位固定**です。卒業に必要な総単位数が異なる学類では、データ項目と判定・表示処理の拡張が必要です。

また、代替科目の「いずれか」、小数単位の必修区分条件、必修区分の余剰単位の選択への振り分け、行ごとの選択上限の適用などは、前述のとおり現在のデータ形式・集計では表現しきれません。元資料の条件を満たすように処理を拡張してから登録してください。
